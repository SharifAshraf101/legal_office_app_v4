# הגשר לאדם – הוראות עבודה לאדם

מסמך זה מוסיף לאדם פרק עבודה עם מערכת המשרד. יש להוסיף אותו להנחיות של אדם (פרק "בקשות ממערכת המשרד").

## הזרימה
1. עו"ד שריף לוחץ "שלח לאדם" במסך **מוח התיק** במערכת. נשמרת בקשה עם: המסמך (קישור), פענוח המסמך, הטיוטה הקיימת, הערות התיק, פרטי התיק והנחיות נוספות.
2. אדם (ב-Claude Code או ב-Claude Desktop, בתיקיית הפרויקט) מושך את הבקשה, עובד עליה ומחזיר תוצאה.
3. התוצאה מוצגת בכרטיס **"טיוטת אדם"** במסך מוח התיק: טיוטה משולבת, טבלת השוואה, מחלוקות, תשובות יוסף וסעיד.

## פקודות
```
node scripts/adam-bridge.mjs list                      # בקשות ממתינות
node scripts/adam-bridge.mjs take <id>                 # לקחת בקשה (נשמרת ב-~/adam-jobs/<id>/package.json)
node scripts/adam-bridge.mjs progress <id> "<הודעה>"   # שורת מצב שמוצגת במערכת
node scripts/adam-bridge.mjs result <id> <file.json>   # שליחת התוצאה
node scripts/adam-bridge.mjs fail <id> "<סיבה>"        # דיווח על כישלון
node scripts/adam-bridge.mjs ask <id> <questions.json>  # שאלות לעו"ד שריף – נפתח טופס במערכת
node scripts/adam-bridge.mjs wait <id> [דקות]          # המתנה לתשובות (ברירת מחדל 30)
```

## שאלות לעו"ד שריף
כשחסרות עובדות, אדם לא שואל בצ'אט אלא במערכת: כותב `~/adam-jobs/<id>/questions.json` – מערך של `{"q":"שאלה","hint":"דוגמה / פורמט"}`, בשפת הבקשה – ומריץ `ask <id> ~/adam-jobs/<id>/questions.json` ואחריו `wait <id>`. במסך מוח התיק נפתח טופס; כשעו"ד שריף שולח, `wait` מדפיס את השאלות והתשובות (נשמרות גם ב-answers.json) ואדם ממשיך. אם `wait` הסתיים בלי תשובה – להריץ `wait` שוב.

## שלבי העבודה של אדם על בקשה
1. `list` → `take <id>`. לקרוא את package.json: `language` קובעת את שפת התוצר (ar – ערבית בלבד, he – עברית בלבד). `request` – הנחיות עו"ד שריף לבקשה זו. `docLink` – קישור למסמך (Dropbox); לקרוא את המסמך עצמו אם ניתן.
2. לפעול לפי שלבי העבודה של אדם: מיומנויות המשרד, כללי התוכן המחייבים, טיוטת עבודה (Draft A).
3. **התממה (חובה)** לפני כל שליחה ליוסף או לסעיד: להחליף שמות הצדדים, הקטינים, עורכי הדין, מספרי זהות, מספרי תיק, כתובות, טלפונים ותאריכי לידה בכינויים ("התובעת", "הנתבע", "הקטין א'"). לשמור את טבלת ההחלפה רק אצל אדם (`~/adam-jobs/<id>/mapping.json`), ולא לשלוח אותה. להציג לעו"ד שריף את החבילה המותממת ולקבל אישור, אלא אם הורה אחרת.
4. **יוסף**: בדפדפן Chrome – הפרויקט "יוסף" ב-chatgpt.com. **סעיד**: ה-Gem "סעיד" ב-gemini.google.com. לשלוח לכל אחד את ההנחיה שלו (שלב 5.3) + החבילה המותממת, ולקרוא את התשובות. בין השלבים: `progress <id> "מתייעץ עם יוסף…"` וכו'.
5. השוואה ושילוב (שלב 6): טבלת השוואה, טיוטה משולבת (Draft B) עם השמות האמיתיים (החזרה מהמיפוי), רשימת מחלוקות.
6. כל אסמכתא של יוסף או סעיד – לאמת (דין רגע / רשת). מה שלא אומת – לסמן "[לאמת]" ולהכניס ל-`toVerify`.
7. לכתוב `~/adam-jobs/<id>/result.json` ולהריץ `result <id> ~/adam-jobs/<id>/result.json`.

## מבנה result.json
```json
{
  "draft": "הטיוטה המשולבת (Draft B) עם השמות האמיתיים",
  "summary": "הודעה קצרה לעו\"ד שריף: מה הוכן, כמה עמודים, מה דורש השלמה",
  "comparison": [{ "claim": "", "adam": "", "yosef": "", "saeed": "", "assessment": "", "recommendation": "לשלב / להשאיר / להסיר / מחלוקת" }],
  "disputes": [{ "point": "", "adam": "", "yosef": "", "saeed": "" }],
  "yosef": "תשובת יוסף (מותממת, כפי שהתקבלה)",
  "saeed": "תשובת סעיד (מותממת, כפי שהתקבלה)",
  "toVerify": ["השלמות ואסמכתאות שלא אומתו"],
  "devilsAdvocate": "הטענה החזקה ביותר של הצד שכנגד והמענה"
}
```

## חיסיון
- חבילות הבקשה נשמרות מחוץ לפרויקט (`~/adam-jobs`) ולא נכנסות ל-git.
- ליוסף ולסעיד נשלח רק תוכן מותמם. `yosef` ו-`saeed` ב-result.json – בנוסח המותמם בלבד.
